# 托管视频持久队列

这是当前源码与离线隔离验证说明，未表示已部署或真实视频已验证。会员网页账号没有已核实的无限并发承诺；以下上限是本项目运行策略。

本机新增超级账号视频策略，尚未部署，也没有修改真实账号或生产数据库。2026-10-22 已完成构建和全量离线测试。高级账号仅暂停新的付费视频提交，图片与图片高清规则保持；完整手机号和等级后缀不改名、不全局停用账号。高级原视频继续按原账号查询、回存和核账，未知回执保留原槽，不换号重提。高级原样片的新付费高清转换明确拒绝，不能转交超级账号；已经提交的转换仍沿原任务查询。

`GET /v1/videos/policy` 仅校验原托管调用 Key 后返回
`{accountPolicy:"super-only",videoQueuePolicy:"serial-submit-on-accepted-v2",longVideoPolicy:"official-long-video-v1"}`，不选账号、不读任务、不查询上游报价或写入业务数据。主 API 在首次付费提交前确认这三个契约版本，避免新 API 误连旧 CPA；原任务查询、取消、回存和核账不受此门禁影响。

`/v1/tasks` 的视频统一在 CPA 排队，主项目只保存同一 CPA ID、镜像状态并查询结果。旧同步 `/v1/videos/generations` 和聊天视频别名在任何账号选择或提交前明确拒绝，历史查询保留。默认 `JIMENG_VIDEO_ACCOUNT_CONCURRENCY=1`，总容量按当前合格超级账号的可用槽位自动扩展；新增第三个或以后更多账号不需要重启或改码。可显式设置 `JIMENG_VIDEO_CONCURRENCY` 作为运维总上限，两项设置都只接受 1–100 的整数。访问租约不是占槽；所有 API Key 共用同一队列与账号活动数。新任务只选择启用、未冷却、名称去空白后以 `_超级` 结尾且最近成功查询余额至少 5 积分的账号，按活动数最少、余额最多、既有选择序号排序。账号停用、冷却或余额不足时不再新增槽位，原在途与未知占用仍按原绑定保留。

账号选择、查询凭据、余额快照和 `provider_hold=1` 在同一 SQLite IMMEDIATE 事务中绑定。指定账号仍要求调用 Key 的原租约，不绕过模型、余额或并发规则；新任务不预先借余额查询绑定某个账号。已绑定任务不换账号。

状态为 `queued → preparing → submitting → running → succeeded/failed`。输入准备失败或未提交的取消可释放占槽；同一次生成的完整明确业务拒绝须有受限响应证明及原身份CAS守卫，不能仅凭错误数字释放。付费POST开始后的网络故障或缺少history ID为 `uncertain`，保留原身份和资金。取消只是停止用户等待，后台只用原凭据、原history查询，不重发。原history已持久化的渲染任务可让出上传提交槽，成功等待账单也不占提交槽，但 `provider_hold`、原凭据与冻结预留继续核对；提交槽与资金预留不是同一状态。没有history的未知请求不能按超时自动释放。

排队期限从接受任务起为 30 分钟，排队超时不会付费提交；实际占槽派发时重置为完整 30 分钟执行期限，返回 `deadlineAt` 供主项目和页面更新。运行任务越过原期限继续查询原历史，不提交第二次。主项目查询 404 超过 90 秒仍保留原任务与未知占用，不据此判失败或释放。参考媒体签名地址在派发时若失效，会在素材准备阶段失败，不自动重新上传或付费重提。主项目保持原成员成果归属与实际管理员计费账号；队列 owner 是 CPA 托管 API Key 的整数 ID，不是画布用户 ID。

`provider_status` 与页面 `status` 分开保存；页面已取消而上游随后成功，仍按实际上游成功结算，不把实际成本归零，也不下载取消的结果。`provider_hold` 未解除的终态继续后台查询，不提前结算。首次新增该列时才迁移旧未知占用；已按精确任务 ID 明确解除的 0 不会在重启或查询时重新标为 1。

## 持久化与迁移

### 本机强制中断与人工核对

本项是新增本机代码，尚未部署、未修改真实任务或资金。2026-10-22 的构建和离线隔离测试已通过，私有日志保存在被忽略的 `.private/`。

- `GET /v1/tasks/:id/interrupt` 仅按原API Key owner读取本地任务快照，返回 `task` 及 `interruption` 的active、phase、canRelease、submissionReleased、review和可选paidStartedAt；不触发查询、队列或账务写入。
- `POST` 同路径默认只中断本任务当前执行；task scope的AbortSignal覆盖HTTP、图片／音视频上传、媒体子进程及独立浏览器上下文。等待全部并行请求实际退出后才结束active；25秒未收口返回503，原占槽和预留保留。
- 人工核对POST须为 `{confirmNoRecord:true,review}`。仅原owner、原任务／账号／付费发送时间／报价及未知状态仍匹配、无history／成果且无活动执行时允许CAS写 `operator_confirmed_no_record` 标记。原 `provider_hold=1`、凭据、状态与资金保留，不补单或自动迁移旧标记。
- 已受理任务继续原history查询，按钮不保证取消远端生成；排队或未付费准备取消不能在重启后再次派发。丢回执只能读取最新状态，不自动重发操作。坏报价或不匹配身份按未知预留保守阻止新增付费，不按零金额处理。

主项目另按原工作台归属与实际操作者鉴权，强断前精确暂停后续批次，避免页面自动开始下一笔；这里只认可原托管Key owner，不接受浏览器自行指定其他账号或任务身份。

`canvas_tasks` 追加 `payload_path`、`requested_account_id`、`provider_hold`、`paid_started_at`、`provider_status`、`credit_before`，不重建或删除原表。字段与首次旧占用迁移在同一事务中完成；旧 `submitting/running/canceled` 视频，以及公开错误明确写“提交结果未确认/提交失败或结果未确认”的视频，保留原绑定并转为占用。没有合法明确拒绝回执时，通用错误不能视为未提交。

旧记录可能没有凭据。新代码不会补猜终态或删除它们；同一账号的多条未知旧记录继续占用该账号的槽，显式总并发上限仍计算所有未解除占用。非超级历史任务保留原查询和占用信息，但不加入新视频池。

输入保存在 `dirname(DB_PATH)/private/video-queue/`，必须与数据库一起位于持久挂载；加密复用既有 `JIMENG_ACCOUNT_POOL_KEY/ACCOUNT_POOL_ENCRYPTION_KEY`，不创建临时密钥。目录 0700、文件 0600。先写独立临时文件、fsync、原子 hard link 发布且不覆盖同指纹文件，Linux 再 fsync 目录，之后插入 SQLite；SQLite 两个写连接均为 FULL 同步。SQLite 持久化付费开始标记后才发 POST。成功受理、确定失败或取消未提交后删除输入；删除失败仅留下不可重提的加密输入，不改变已记录状态。断电可能留下无数据库行的加密孤立文件，不能据此重提或批量删除仍被任务引用的输入。

重启只将 `preparing + paid_started_at=0 + 有输入` 退回队列，旧 `submitting` 一律标为未知并持有账号。付费标记之后的进程中断，即使恰好尚未传到上游，也不重放 POST。

发布前必须在线备份数据库及 WAL、同一私有队列目录和稳定密钥配置（不得输出密钥），按精确任务 ID 核对旧占用、账号与 history/凭据是否存在。现有旧失败没有 history 或凭据时，需要用户核对即梦生成历史并明确释放决定，不能声称两个账号都已可用。

旧代码忽略新增字段，而且不会派发 `queued`；不能在排队、运行或未知占用未处置时直接回滚 CPA。回滚不回灌旧数据库；须先保存新代码及原数据库/队列的在线备份，保留新队列处理器直到已提交任务确认终态，或明确停止新视频提交并保留未知占用，由用户决定处置。主 API/Web 可独立回退，但旧页面仍应只查原任务，不能借回退触发生成。

`GET /v1/videos/quote` 只读同一可用超级视频账号池的官方模型配置、精确视频计费项元数据和 UserCredit 支付策略，全局一分钟快照合并员工查询，不混入高级账号报价。单一价显示单值，多个超级账号官方价不同仍保留真实区间。参数使用当前模型协议以及实际参考视频秒数 `referenceVideoSeconds`；有分辨率价格列表时沿用官方规则计输出加参考视频秒数，普通 2.0 无列表时只计输出秒数，但参考视频采用独立费率。`amount=0` 按官方倍率 1 处理，不视为免费。报价返回官方积分区间和 `basis=credit-strategy`，成功或不可用响应均携带 `accountPolicy=super-only`，不占生成槽、不租账号、不预扣；免费与优惠权益仍以实际结算为准。
