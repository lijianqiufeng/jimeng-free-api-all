## 视频安全合同

- 新视频只使用启用、未冷却、余额与动态能力满足要求且名称以 `_超级` 结尾的账号。
- 所有管理 Key 共用一条持久队列。上传与付费提交按账号串行；取得正式历史编号后可以释放提交槽，资金预留保留到逐单核账完成。
- 付费 POST 的回执不明时保留原账号、原任务与预留，不换账号、不自动重提。
- 旧同步视频入口 `/v1/videos/generations` 已停止，调用方必须使用 `/v1/tasks`。
- `/v1/videos/policy` 返回账号、队列和长视频合同版本；调用方应在首次付费提交前校验。
- 具体规则见 [VIDEO-QUEUE.md](VIDEO-QUEUE.md) 和 [LONG-VIDEO.md](LONG-VIDEO.md)。


`npm run test:offline` 会逐个打包测试文件，在独立临时数据库与媒体目录中运行，并禁止未模拟的网络访问。测试日志只写入被忽略的 `.private/`。2026-10-22 的完整运行覆盖 19 个测试文件、195 条断言，全部通过；同步上游或修改代码后必须重新运行。

真实付费测试、生产数据库迁移和部署不属于离线测试。进行这些操作前需单独确认账号、积分、备份、候选镜像和回滚方案。

## Git 与工作区约定

- `main` 用于跟踪稳定主线；功能开发使用 `work/*` 分支。
- 提交源码、测试和说明文档；不要提交 `.private/`、`data/`、`logs/`、`dist/`、`node_modules/`、`outputs/` 或 `portable-release/`。
- `portable/` 是便携版源码与脚本，需要纳入版本控制；`outputs/` 和 `portable-release/` 是本地生成物。
- 账号 Cookie、管理 Key、数据库、真实任务证据和测试日志只保存在已忽略目录或运行环境中。
- 同步上游前先保证工作区已提交并通过离线测试；同步后再次构建和运行完整离线测试。
- 发布前核对 `git status`、版本号、数据库迁移、环境变量、镜像摘要以及 `/ping` 与根页面。
